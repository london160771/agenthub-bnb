AGENTHUB — BNB CHAIN HACKATHON
FULL MVP BUILD SPECIFICATION FOR CODEX

Version: 1.0
Purpose: Turn this specification into a working, polished hackathon MVP.

============================================================
1. PRODUCT OVERVIEW
============================================================

Product name:
AgentHub

One-line description:
AgentHub is a discovery, evaluation, comparison, and hiring marketplace for AI agents on BNB Smart Chain.

Core problem:
There are many AI agents in the BNB ecosystem, but users need a simple way to discover what agents do, evaluate whether they are trustworthy and active, compare alternatives, and hire an agent to perform a task.

Core product promise:
DISCOVER → EVALUATE → COMPARE → HIRE → EXECUTE → VERIFY

Important scope decision:
Do NOT build dozens of new AI agents. Use existing BNB/ERC-8004 agents wherever practical. Build the marketplace/discovery layer. If an existing agent cannot be integrated in time, create a small number of simple demo/adapter agents or use clearly labeled seeded data for non-critical marketplace entries.

The MVP must feel like a real product, not a CRUD hackathon demo.

============================================================
2. HACKATHON STRATEGY
============================================================

Primary goal:
Build the strongest possible marketplace/discovery experience for the BNB Chain hackathon.

Secondary goal:
Support the TermiX-style "Agent Advantage" story by measuring whether hiring an agent is better than doing the same task manually.

Do NOT spend time on:
- Building a new blockchain
- Building a new AI model
- Building dozens of agents
- Multi-chain support
- Agent DAO/governance
- Full agent creation/publishing platform
- Complex agent-to-agent orchestration
- Production-scale infrastructure
- Full trading automation
- High-risk financial execution

Priority:
Tier 1 features are mandatory.
Tier 2 features should be built after Tier 1 works.
Polish and reliability are more important than adding Tier 3 features.

5. MAIN USER JOURNEY
============================================================

Scenario:
A user wants an agent to monitor a DeFi lending position.

Flow:

Landing
→ Find Agent
→ User types natural-language request
→ AI interprets task
→ Recommended agents appear
→ User opens agent profile
→ Reviews identity/trust/performance
→ User compares another agent if desired
→ User hires selected agent
→ Connects wallet
→ Configures task
→ Confirms
→ Agent executes
→ Result displayed
→ Agent Advantage displays time/cost benefit
→ Execution appears in activity history

This journey must be extremely polished.

37. FINAL PRODUCT STORY
============================================================

Do not pitch AgentHub as:
"Just another AI agent directory."

Pitch it as:

"There are thousands of AI agents in the BNB ecosystem, but users still need to figure out which agent actually does what they need, whether it is trustworthy, how it performs, and whether hiring it is worth it.

AgentHub turns the BNB agent ecosystem into a searchable, verifiable marketplace where users can discover, evaluate, compare, hire, and measure agents."

Core message:
Discover → Evaluate → Compare → Hire → Execute → Verify

Differentiators:
1. Natural-language agent discovery
2. Explainable trust score
3. ERC-8004 identity
4. Performance/reputation data
5. One-click hiring
6. Agent Advantage: measurable benefit vs manual work

38. IMPLEMENTATION RULES FOR CODEX
============================================================

1. Build incrementally.
2. Do not attempt the entire application in one generation.
3. Keep the application runnable after every major milestone.
4. Do not invent BNB Chain APIs, contract addresses, ERC-8004 endpoints, or x402 implementation details. Verify current official docs first.
5. Prefer official BNB Chain documentation and SDKs for blockchain integrations.
6. If an integration is unavailable or too risky for the MVP, create a clean adapter interface and use seeded/demo data behind it.
7. Keep real and demo data distinguishable.
8. Do not fabricate on-chain statistics.
9. Use reusable React components.
10. Avoid giant monolithic components.
11. Keep secrets server-side.
12. Use environment variables.
13. Add clear error handling.
14. Add loading and empty states.
15. Make the UI responsive.
16. Keep code readable and maintainable.
17. Add comments only where they provide useful context.
18. Prefer simple architecture over premature abstraction.
19. Do not add Tier 3 features unless Tier 1 and Tier 2 are complete and stable.
20. Do not sacrifice the core user journey for secondary features.
