1. PROJECT OVERVIEW AND PURPOSE
--------------------------------------------------------------------------------
AgentHub is a marketplace for AI agents on BNB Smart Chain, built for a BNB
hackathon as a polished, deployable Web3 SaaS MVP.

The product is organised as a six-step user journey, and the phases follow it:
  DISCOVER -> EVALUATE -> COMPARE -> HIRE -> EXECUTE -> VERIFY

The differentiator is HONESTY ABOUT DATA PROVENANCE. Every value shown to a user
carries a per-field badge saying where it came from: `chain` (read live from BNB
testnet), `derived` (arithmetic on chain data, with the assumption stated),
`input` (the user supplied it), `simulated` (modelled — currently one file only),
or `unavailable` (deliberately withheld rather than invented). This is the
project's core claim and its main defence; do not weaken it.

Secondary theme: "Agent Advantage" — proving that hiring an agent beats doing the
task by hand, using measured numbers only.

7. IMPORTANT ARCHITECTURE / TECHNICAL DECISIONS
--------------------------------------------------------------------------------
A1. PER-FIELD PROVENANCE, NOT PAGE-LEVEL FOOTNOTES. Every output value carries
    its own badge. A simulated headline number also gets a dotted warn-coloured
    underline. Do not replace this with a single page disclaimer.

A2. output SHAPE (the contract between executors and the UI):
      { fields[], recommendation, hasSimulated, provenance, reads[] }
    Each field: { key, label, value, source }. Rendered by
    frontend/src/components/execution/ExecutionResult.jsx as a FLAT <dl>.
    THERE IS NO TABLE RENDERER. Adding one is planned as `output.tables`.

A3. CATEGORY COUPLING IS SIX PLACES, and all must change together to add one:
      backend/models/Agent.js             AGENT_CATEGORIES
      frontend/src/config.js              CATEGORIES
      frontend/src/lib/hire.js            HIRE_FIELDS
      backend/services/agentExecutors.js  EXECUTORS + ADDRESS_INPUTS
      backend/data/seedAgents.js
      frontend/src/pages/LandingPage.jsx  CATEGORY_ICONS  (easy to miss;
                                          falls back to `Compass`)
    Category FILTERING and COUNTING are fully generic off AGENT_CATEGORIES and
    need no change.

A4. Mongoose exclusion projection PROJECTION = '-__v -_id' means any new schema
    field is AUTOMATICALLY exposed by the API. Convenient, but it also means a
    half-finished field leaks. Be deliberate.

A5. SUB-DOCUMENT DEFAULTS HAZARD. Execution.advantage MUST keep `default: null`
    and MUST NOT have subfield defaults. A sub-document default makes Mongoose
    materialise an empty object on every hire, which reads downstream as "a
    measurement was taken and came back zero". This is load-bearing.

A6. AdvantageSchema enforces three rules on purpose: no defaults on any field;
    provenance (manualMethod, evidenceRef, measuredBy, measuredAt) required if
    the object exists at all; a metric cannot appear without its definition
    (stepDefinition with step counts, qualityRubric with quality scores).

A7. BigInt-only arithmetic for chain values (see weiToDecimalString in
    blockchainService.js). Never use floats for token amounts or wei.

A8. Backend input validation is STRUCTURAL ONLY, by deliberate trade-off.
    executionController.js: MAX_INPUT_KEYS = 12, MAX_INPUT_VALUE_LENGTH = 500,
    MAX_TASK_LENGTH = 300, and parseInput accepts ONLY string/number/boolean
    primitives — no arrays, no nested objects. Category-specific rules live in
    the frontend where the field schema is, because duplicating them server-side
    would guarantee drift.

A9. Retry is folded into POST /api/executions/:id/run. THERE IS NO /retry ROUTE.
    `failed` -> resetForRetry then re-run; `running` -> started:false;
    `completed` -> 409.

A10. config/env.js is the single place to read process.env. Known violation:
     blockchainService.rpcUrl() reads process.env.BNB_TESTNET_RPC_URL directly.
     Worth fixing when next touching that file.

A11. provenanceHost exposes only the RPC HOSTNAME, never the full URL, because a
     configured RPC URL can carry an API key.
