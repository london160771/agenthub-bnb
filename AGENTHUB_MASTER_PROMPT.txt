AGENTHUB — CODEX MASTER EXECUTION PROMPT

ROLE

You are the lead software engineer responsible for turning the attached
AGENTHUB_BNB_HACKATHON_MVP_CODEX_SPEC.txt specification into a working,
polished, deployable application.

The specification is the source of truth for the product.

Your job is to:
1. Understand the product before coding.
2. Build the application incrementally.
3. Keep the app runnable throughout development.
4. Prioritize Tier 1 features.
5. Build Tier 2 only after Tier 1 is stable.
6. Verify BNB Chain/ERC-8004 integrations against current official
   documentation instead of guessing.
7. Make reasonable implementation decisions without constantly asking
   for approval.
8. Stop and ask for clarification only when a decision materially
   changes the product, security, architecture, or hackathon scope.

The final result should feel like a serious Web3 SaaS product, not a
basic CRUD dashboard.

2. PRODUCT NORTH STAR

The entire application must optimize for this journey:

DISCOVER
↓
EVALUATE
↓
COMPARE
↓
HIRE
↓
EXECUTE
↓
VERIFY

A user should be able to say:

"I need an agent to monitor my DeFi position."

Then:
1. AgentHub understands the request.
2. AgentHub recommends suitable agents.
3. User examines the agent.
4. User sees identity and reputation.
5. User compares alternatives.
6. User hires the agent.
7. User connects their wallet.
8. Agent executes the task.
9. User sees the result.
10. User sees the execution in their history.
11. User sees measurable Agent Advantage.

Every major design and engineering decision should support this journey.


3. DO NOT BUILD THE WRONG PRODUCT

AgentHub is NOT:
- An AI chatbot.
- An AI agent creation platform.
- A generic SaaS dashboard.
- A crypto trading terminal.
- A portfolio tracker.
- A collection of fake AI agents.
- A simple directory.

AgentHub IS:

A marketplace and discovery layer for AI agents on BNB Smart Chain.

The product should make it easy to answer:
1. What does this agent do?
2. Can I trust it?
3. How well has it performed?
4. How much does it cost?
5. How is it different from another agent?
6. Can I hire it?
7. What happened when it executed?


4. IMPLEMENTATION PHILOSOPHY

Build vertically, not horizontally.

Do not build every frontend page first and then discover that the
backend doesn't support the product.

Instead, build complete vertical slices.

Example:
Marketplace card → Agent API → Agent database → Agent detail page

Then:
Finder UI → Finder API → recommendation logic → recommendation results

Then:
Hire UI → wallet → backend → execution → result

This keeps the product functional throughout development.

PHASE 6 — TRUST SCORE

Initial scoring:
30% Identity
25% Success Rate
20% Activity
15% Reliability
10% Reviews

- reduce confidence,

PHASE 7 — AI AGENT FINDER

Build:
/find

Example request:
"I need an agent that monitors my Venus lending position and warns
me before liquidation."

Backend:
1. Receive request.
2. Use an LLM to classify intent if configured.
3. Extract category, skills, protocol and task type.
4. Query compatible agents.
5. Calculate deterministic match scores.
6. Return ranked agents.

Scoring:
40% task compatibility
20% skill compatibility
15% trust
10% success
10% price
5% activity

AI assists interpretation but does NOT control ranking unrestrictedly.

If no AI API key exists, implement a keyword/rule-based fallback.

The app must not break when the AI provider is unavailable.
